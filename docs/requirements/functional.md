# Функциональные требования

## 1. Роли

- **Гость** — может просматривать объявления, искать вещи, открыть подробности, разместить временное гостевое объявление и отправить жалобу.
- **Зарегистрированный пользователь** — может выполнять действия гостя, входить в профиль и управлять собственными объявлениями.
- **Администратор** — может просматривать и искать пользователей и объявления, работать с жалобами и выполнять административные действия.

## 2. Требования

|  | Требование | Критерий |
|---|---|---|
| 1 | Система должна отображать главную страницу с категориями, поиском и блоками недавно найденных и потерянных вещей. | На главной видны категории и доступен переход к списку объявлений. |
| 2 | Система должна показывать каталог объявлений и позволять переходить к объявлениям выбранной категории. | После выбора категории список содержит объявления этой категории. |
| 3 | Система должна выполнять поиск объявлений по введённому запросу. | Результаты соответствуют поисковому запросу; при отсутствии совпадений показывается пустой результат, а не ошибка. |
| 4 | Система должна показывать страницу подробностей объявления с названием, описанием, статусом «Найдено/Потеряно», категорией, датой, местом, контактами и вложением, если оно есть. | Поля, сохранённые для объявления, отображаются корректно. |
| 5 | Система должна позволять посетителю создать гостевое объявление без входа в аккаунт. | Валидная форма создаёт объявление; пользователю показывается предупреждение о сроке хранения 7 дней. |
| 6 | Система должна позволять зарегистрированному пользователю создавать объявления. | Объявление сохраняется со ссылкой на учётную запись автора. |
| 7 | Форма объявления должна поддерживать название, описание, статус, категорию, контактные данные, местоположение и одно вложение. | Данные формы сохраняются и доступны на странице подробностей. |
| 8 | Система должна принимать для объявления не более одного файла размером до 10 МБ в форматах JPG/JPEG и PDF, как указано в текущем интерфейсе. | Допустимый файл принимается; недопустимый формат, превышение размера или второй файл отклоняются с понятным сообщением. Проверка выполняется на сервере. |
| 9 | Система должна валидировать введённые значения и проверять существование выбранной категории. | Некорректные данные не записываются в БД; пользователь получает описание ошибки. |
| 10 | Система должна предоставлять регистрацию, вход и выход из учётной записи. | Валидные данные позволяют войти; выход завершает сессию; неверные данные не создают авторизованную сессию. |
| 11 | Система должна предоставлять восстановление пароля с использованием ограниченного по сроку токена. | Просроченный или уже использованный токен не позволяет изменить пароль. |
| 12 | Система должна отображать профиль пользователя с персональными данными, количеством его объявлений и списком объявлений. | В профиль выводятся данные только соответствующего пользователя. |
| 13 | Система должна позволять владельцу объявления редактировать его поля и менять вложение. | Изменять объявление может только его владелец или администратор; обновлённые данные отображаются после сохранения. |
| 14 | Система должна позволять владельцу удалить своё объявление. | После подтверждённого удаления объявление недоступно в каталоге; связанный файл обрабатывается согласно правилам хранения. |
| 15 | Система должна позволять отправить жалобу со страницы подробностей объявления. | После отправки пользователь получает подтверждение, а жалоба сохраняется как отдельная запись и доступна администратору. |
| 16 | Система должна предоставлять администратору список жалоб и возможность отметить результат рассмотрения. | Для жалобы фиксируются статус, время и администратор, выполнивший обработку. |
| 17 | Система должна показывать административную статистику пользователей и предоставлять поиск пользователей по доступным полям. | Администратор может найти запись и увидеть связанные показатели, включая число объявлений и жалоб, если эти показатели рассчитаны системой. |
| 18 | Система должна предоставлять администратору список и поиск объявлений. | Поиск позволяет найти объявление и перейти к его административному представлению. |
| 19 | Система должна предоставлять администратору удаление учётной записи. | Действие доступно только администратору; правила обработки объявлений и жалоб, связанных с удаляемой учётной записью, должны быть определены отдельно. |
| 20 | Система должна обрабатывать объявления по `expires_at`; гостевое объявление имеет срок действия 7 дней. | Просроченные объявления обрабатываются автоматически по расписанию или эквивалентному механизму; повторный ручной запуск не приводит к ошибке. Политика удаления/архивации должна быть утверждена отдельно. |
| 21 | Система должна предоставлять административный просмотр и очистку просроченных объявлений. | Администратор может просмотреть просроченные записи и выполнить разрешённое действие; фоновая обработка остаётся основным способом регулярного обслуживания. |
| 22 | Система должна показывать правовую информацию и ссылку на политику конфиденциальности. | Страницы доступны из соответствующих частей интерфейса; при регистрации пользователь может подтвердить согласие с политикой, как показано в текущей форме. |
| 23 | Система должна разграничивать действия гостя, пользователя и администратора на стороне сервера. | Прямой запрос к защищённому действию без необходимых прав отклоняется, даже если пользователь обошёл интерфейс. |
| 24 | Система должна согласованно сохранять данные объявления и путь к его вложению. | При ошибке загрузки или записи система не оставляет объявление с несуществующим вложением и не показывает ложное сообщение об успехе. |
