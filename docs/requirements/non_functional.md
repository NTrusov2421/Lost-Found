# Нефункциональные требования (NFR)

### 1. Производительность и масштабируемость
*   **Время отклика:** Страницы должны загружаться не дольше **2-3 секунд** при обычной нагрузке (до 1000 объявлений).
*   **Оптимизация:** Для ускорения поиска и фильтрации обязательно использовать индексы в базе данных (по категориям, статусу и дате).
*   **Масштабируемость:** Добавление новой категории должно происходить через админ-панель (в БД), без необходимости править PHP-код.

### 2. Безопасность
*   **Пароли:** Хранить только в виде хэша.
*   **SQL-инъекции:** Все запросы к БД выполнять только через подготовленные выражения (PDO/Prepared Statements).
*   **XSS-атаки:** Экранировать весь пользовательский ввод при выводе в HTML.
*   **CSRF-защита:** Формы создания объявлений и авторизации должны иметь CSRF-токены.
*   **Загрузка файлов:** Жестко ограничить размер (до 10 МБ) и формат файлов (только JPG, JPEG, PDF). Переименовывать файлы при загрузке.
*   **Доступы (RBAC):** Обычный пользователь не может удалить чужое объявление или зайти в панель администратора (проверка прав на сервере).

### 3. Удобство использования (UI/UX)
*   **Адаптивность:** Сайт должен корректно отображаться на экранах смартфонов (начиная с ширины 360px) без горизонтальной прокрутки.
*   **Понятность:** Пользователь должен интуитивно понять, как подать объявление или найти вещь, без чтения инструкций.
*   **Валидация:** При ошибке ввода (например, неверный email) форма не должна очищаться полностью; ошибка подсвечивается рядом с конкретным полем.

### 4. Надежность и обработка ошибок
*   **Обработка исключений:** При ошибке сервера или БД пользователь должен видеть причину в понятной форме.
*   **Автоматизация (Cron):** Задача удаления просроченных гостевых объявлений (через 7 дней) должна запускаться автоматически (по расписанию) и не ломать БД при повторном запуске.

### 5. Поддерживаемость (Чистота кода)
*   **Разделение логики:** Код должен быть разделен на слои (например, отдельно работа с БД, отдельно HTML-шаблоны, отдельно логика).
*   **Комментирование:** Сложные участки кода (например, логика проверки срока действия токена или удаления файлов) должны быть прокомментированы.
